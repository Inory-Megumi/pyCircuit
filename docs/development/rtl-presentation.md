# Physical RTL 展示层

本地 `codex/rtl-readable-20261105` 在现有 physical 导出器中加入只读展示计划。
使用原命令即可启用：

```bash
pycircuit emit counter.ac --target verilog --rtl-mode physical -o physical
```

输入是已经验证的同一份 final IR。展示计划不修改 IR、不增加语义 use，
不改变 Rule 调度、DWire、状态更新、检查或物理接口的含义。默认 managed 输出
和 C++ 路径保持原行为；没有新增语言语法或 synthesis 模式。

## RTL 中能看到什么

- 原状态/DWire 名字，例如 `count`、`inc`、`dec`。派生状态输入使用
  `count_next`、`count_write`；其他值按实际 Rule 和操作命名。
- physical 名字独立分配：端口按定义、方向和序号标识，状态及局部值按 IR
  身份标识；预留端口、参数和检查协议名，重名只添加确定的局部后缀。
  同定义的多个实例仍是多个真实实例，不因同名而合并。
- 普通信号集中声明。组合语句按实际根 Rule 分区，附定义位置；外层共享
  组合逻辑单列。端口连接、检查及状态/子模块实例保留独立的输出区域。
  Table 生成块内的局部变量仍留在原块中。
- 精确常量和同宽完整提取/转换的别名直接展示；小型、单消费者的标量
  表达式可以展开。共享计算、跨 Rule 的非恒定值和较大的表达式保留名字。
  展开保留原 wire 的位宽和无符号边界。
- 等价事实先用于归并展示值，再重建活跃依赖、消费者和展开成本，最后分配
  信号名。计数器的更新条件直接成为 `count_write = (inc != dec)`，不再
  经过多根仅复制值的临时线。原 IR 身份及来源仍保留在映射里。
- 初始化使用同一个确切别名解析器；计数器只生成
  `localparam logic [7:0] count_init = 8'd3`。名义类型构造和实际宽度转换
  仍保留，不将 Struct/Enum 初始化无条件扁平化。
- 静态表达式打印器记录 `floordiv`、`mod` 的依赖，在定义、类型和 wrapper
  打印完成后生成需要的函数。无名义类型、无这些依赖的计数器不生成空包。
  符号位宽、索引所需函数仍会保留；managed 的函数集合和输出合同不变。

分区顺序不代表执行顺序。显式 `schedule` 的状态前递已经存在于输入 IR；
展示层只把原来的连接显示出来，不生成新的仲裁、流水级或回滚关系。
多个 Rule 共同参与的外层连接不会被任意归给其中一条 Rule。

## 自动端口和类型打印

physical 的自动时钟、复位从已验证的 `ac.domain_inputs` 序号识别，默认
打印为 `clk`、`rst`，不依赖 `pyc_clk` 等源码拼写，也不在生成的 RTL 上
做替换。若用户已有数据端口 `clk`，保留该名字，自动时钟改用 `clk_2`。
模块声明、输入值、输出赋值、父子模块连接、wrapper 和 `ports.json` 使用
同一个按定义缓存的名字表。`ports.json.name` 保留源码身份，`wire` 表示
实际 RTL 名字；`domains` 继续使用端口序号。

功能模块不再增加 `root_commit_ok`、`reset_active`、`local_error` 检查端口。
物理顶层名为 `design_top`；它只适配功能端口。
physical 名字转义使用 `id_`，冲突在所属模块内消解；共享 C++/managed
名称合同不变。已有下游应读取新生成的清单，不能沿用旧的编码端口名。

位宽直接来自类型：`bits[1]` 打印为 `wire`/`logic`，`bits[8]` 打印为
`wire [7:0]`/`logic [7:0]`。闭合静态表达式计算上下界，符号参数保留
表达式；一位 packed Table 保留 `[0:0]`，以支持合法的索引和 part-select。
名义 Struct/Enum 保留其类型身份，不把结构体接口扁平成无类型位向量。

经物理投影验证的 DFF/DFFE 在声明所属模块内打印直接的时钟更新块，
不再经由 managed 仿真库的私有参数/端口。类型化初始化、同步复位优先级、
使能保持、非阻塞赋值、四态类型/控制检查和全根提交屏障均保留。
检查仍在 `SYNTHESIS` 条件下按原物理导出合同处理。没有修改 final IR，
也没有修改库原语的 C++ 或 managed 实现。
physical 仅打印所选顶层可达的模块，与物理检查和提交端点的分析范围一致；
同一源码文件里未被选中的测试顶层不会附带进入该物理 RTL。

## 模块内部的仿真检查

检查逻辑集中在模块内部的 `checks` generate 区域。复位直接使用已经验证的
本地复位值；错误向父模块汇总，统一更新许可向子模块传递。这些层次连接
由实际实例身份和统一名字表生成，普通实例和 Collection 保留各自的路径。
检查区域及其成员名字不会遮蔽功能端口、表达式或存储输入。

所选导出根模块拥有原来的唯一 sticky fault 状态，汇总全层次错误并报告
一次 `PYCIRCUIT_PHYSICAL_FAULT`。所有存储仍在更新前观察同一许可。
可以直接实例化这个根模块，无需额外接检查线；同一个根模块的多个实例
拥有独立的检查状态，不使用全局包变量。子模块是该导出闭包的一部分；
若要把另一个子模块独立作为根使用，应以它为 top 正常 link/emit。

`SYNTHESIS` 条件下，检查区域、层次检查连接、提交门控和类型检查均不打印，
保留普通的时钟、复位、使能和非阻塞状态更新。仿真验收仍在未定义
`SYNTHESIS` 时执行；没有删除检查或改变四态异常后的全根冻结行为。

## 四态与复杂度

一位控制使用有限的 `0/1/X/Z` 值域，按逐值真值表计算展示事实，保留
同值输入的相关性。只有对所有可能输入都成立的常量/别名才会简化。
例如 `a & 1` 在 `a=Z` 时必须得到 X，不能直接替换成 a。
多位算术和比较不套用二态布尔规则。检查也消费同一份四态事实：原条件
`unknown(path) || (reset===0 && path===1 && unknown(condition))`
中，只有证明恒为零的项才省略。常量路径可去掉多余门控，整个表达式
恒为零时不生成运行时错误线；其原检查身份仍记录为 `proven-zero`。
输入 X/Z、非法控制及存储检查继续保留。这里没有跳过 source-check 验证，
没有放宽证明预算，也没有使用复位有效或输入只含 0/1 的假设。

计划使用缓存的确切别名、显式活跃性和自底向上的工作队列。
单表达式展开成本上限为 12；这是展示大小阈值，不是放宽编译器证明预算。
合法字段依赖在整值图上可能形成环，这些节点保留命名和原有结构，
不新加硬件合法性拒绝。名称后缀维护独立计数，避免同类节点的二次方搜索。

## 来源文件

physical 输出新增 `rtl-names.json`，纳入 `generated.json` 文件清单。
它与既有 `*.source-map.json` 并存，后者的合同不变。

每个模块记录定义身份、RTL 文件/模块名和展示值。每个值包含：

- `id`、操作种类、来源 Location 与可提取的文件/行/列。
- 实际根 Rule 名和注册 occurrence；没有根归属的值不伪造 Rule。
- 展示名、实际渲染内容、消费者和展开成本。
- `disposition`：`signal` 为命名信号，`port`/`region-port` 为接口或生成块绑定，
  `inline` 为展开表达式，`elided` 为在常量/别名展示中无需单独打印的节点。
  `inline`/`elided` 的计划名字不是 RTL 声明。
- `representative` 指向归并后的展示值；`alias` 条目保留原节点身份、来源和
  Rule，同时引用代表值的名字和渲染。`role` 保留推导出的用途名。

模块另有 `source_values`，将归并前的源值、位置映射到展示代表值，覆盖
Rule 捕获/结果及同宽提取等结构别名；同一根 RTL 线可以对应多个源值。
`checks` 记录原检查序号、条件/路径代表值及 `runtime`/`proven-zero` 状态。
`initializers` 将源值序号对应到实际生成的初始化参数名。

这份映射使用真实 IR 来源，不从 RTL 字符串猜测语义。当前不输出精确 RTL
语句行号；可通过 RTL 文件、模块和实际信号名定位。

## 当前范围与检查

复用的是 [archlab 移植研究](rtl-readability-research.md) 的图、来源和共享原则，
实现适配本版本已经保留的 Rule/状态身份。没有整笔合入旧 frontend/Compose。

当前明确保留状态、DWire 和实例名字。已经在前端丢失的任意 Python 局部绑定名
尚不能恢复，使用操作/用途和源位置表示；内联 Method 保持所属原子根，
不伪造独立提交分区。复杂 Table 布局和接口展开仍使用既有打印结构。

针对性测试为 `tests/system/test_rtl_port_names.py`、
`tests/system/test_rtl_presentation.py` 和
`tests/system/test_dwire_physical.py`，配合已有 physical 导出/拒绝测试。
`ACIRRtlPresentationTests` 从后端符号类型接口验证辅助函数依赖；当前 Python
静态注解尚不接受 `//`、`%`，这项后端测试不代表新增前端语法支持。
覆盖共享算术、端口重名、位宽截断、Z/X、DWire 同拍更新与显式调度前递；
记录 Icarus 四态和 Verilator 已知值仿真。同源前后还对照 C++、managed RTL
及 final IR，单独记录 emit 时间和内存；不把这些结果当成通用形式等价或 PPA。
候选绑定的实际运行日志位于忽略目录 `docs/gates/logs/rtl-presentation-20261105/`。
端口/类型后续候选单独记录在 `docs/gates/logs/rtl-ports-20261105/`。
检查接口分离候选记录在 `docs/gates/logs/rtl-check-scope-20261105/`。
归并、恒定检查及依赖按需生成候选记录在
`docs/gates/logs/rtl-normalized-20261105/`；先前候选和回执不变。
